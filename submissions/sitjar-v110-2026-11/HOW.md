Construction: two methods, named per array in claims.csv. (1) CA(291; 3, 32, 5) and CA(884; 3, 58, 7): delete a run and repair by local search, one program per parameter set, written by Claude Opus. (2) The other 6: classic post-optimisation (Nayeri, Colbourn and Konjevod 2013), repeated, of the array named in the construction of each claim.
Built from: (1) our earlier entries in this table, CA(323; 3, 32, 5) and CA(929; 3, 58, 7), through intermediate arrays of the same search. (2) the array named in each claim: our earlier entries CA(36615; 4, 29, 10), CA(78458; 4, 31, 12), CA(225184; 5, 13, 10), CA(30386; 5, 16, 6), CA(42655; 5, 21, 6) and CA(44281; 5, 23, 6), which rest on record arrays of Bai XunDi (doi:10.5281/zenodo.23787055) in this table. Our earlier entries rest on the arrays and constructions listed in their builds_on, which each claim repeats.
Program: https://github.com/tns-research/covering-array-records release v1.10 (doi:10.5281/zenodo.24205260). (1) generators/v1.10/CA_<N>_<t>_<k>_<v>.c, one per array, "gcc -O3 -std=gnu11 -o gen CA_<N>_<t>_<k>_<v>.c -lm; BEST_CANDIDATE=start.txt ./gen > out.txt", where start.txt is the starting array named above. (2) generators/postop.c, "gcc -O3 -march=native -o postop postop.c -lm; ./postop CA_<N>_<t>_<k>_<v>.txt t v <seconds> out.txt" with passes of 300, 1800 and 7200 seconds, each repeated on its own output. The programs of (1) were written by Claude Opus (Anthropic); no LLM runs in them. The searches are randomised and time-limited, so a rerun gives a valid array of similar size.
